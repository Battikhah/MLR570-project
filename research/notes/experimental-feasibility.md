# PCD / FedPCD experimental feasibility and objective choice

Checked 2026-11-02. Hardware assumption supplied in task: Apple M4, 16 GB unified memory, MPS/CPU only, approximately 14 GiB free storage. No training or dataset downloads were run. **VERIFIED** marks paper/owner-page facts; **INTERPRETATION** is design reasoning; **HYPOTHESIS** is an untested prediction; **RECOMMENDATION** is proposed experimental action. All computational costs below are explicitly estimates, not measurements.

## Objective candidates and actual gradient-conflict checks

1. **VERIFIED — EXISTING EMPIRICAL EVIDENCE; RECOMMENDATION:** Primary task accuracy with compression/sparsity/low-rank secondary. This is the best grounded first objective for a PCD-method study: the PCD paper directly tests CIFAR pruning and CIFAR sparsity/low-rank and reports mechanism diagnostics. Caveat: its project page says the compression advantage arose mainly from objective-scale mismatch; raw task/regularizer cosine never exceeded 1.2e-3, so it is weak direct evidence for a “gradient conflict” thesis. Measure per-minibatch raw and normalized cosine, gradient norms, PCD active-set rate, constraint satisfaction, feasibility/fallbacks, primary alignment, achieved sparsity/rank, test accuracy, latency, FLOPs, file size, and wall-clock. Make achieved compression the matched target; compare task loss versus group-lasso/nuclear penalties with tuned scalarization and direct constrained/pruning baselines. A priority formulation is meaningful if accuracy is the deliverable and compression is a required budget.
2. **INTERPRETATION — HYPOTHESIS; RECOMMENDATION:** Global classification objective versus client-specific progress/fairness in federated learning is the strongest alternative and the FedPCD paper directly tests it. Measure per-client gradient/pseudo-gradient cosine to global aggregate, fraction with negative alignment, tail client loss/accuracy, mean accuracy, worst-decile accuracy, spread and Jain index; also measure stale-cache age and QP feasibility. Priority semantics are meaningful when aggregate utility is primary while minimum client progress is an explicit guardrail; a max-min/fairness-weighted objective remains a credible cheaper alternative. Paper evidence is favorable but source-paper comparisons include extensive method-specific tuning and FedPCD uses best τ per setting in some headline text; distinguish fixed τ=0.02 from tuned-τ results. Report the exception where FedLF beats worst-decile performance, plus CIFAR-100 spread caveat.
3. **INTERPRETATION — HYPOTHESIS; RECOMMENDATION:** Ground-truth CE primary versus teacher KL secondary in knowledge distillation (existing course proposal). This aligns with the course project and can measure real conflict directly, but reliability gating (teacher correctness/confidence) changes the secondary data distribution and makes the method’s novelty confounded with sample selection. For each minibatch, record CE/KL raw and normalized cosine, gradient norm ratio, teacher accuracy/confidence/calibration, gate fraction by class and epoch, and fraction of PCD constraint satisfaction; report student top-1, CE, KD divergence, negative transfer versus CE-only, corruption robustness, time and memory. A priority definition makes pedagogical sense only if label accuracy remains the non-negotiable goal. Include ungated/gated weighted KD and matched gate-only ablations before attributing changes to PCD.
4. **INTERPRETATION — HYPOTHESIS:** Robust accuracy primary versus clean accuracy secondary (or vice versa, depending deployment) is measurable on CIFAR-10-C/CIFAR-100-C, but adversarial training compounds compute and “primary” choice is policy-dependent. Use clean/adversarial accuracy, corruption severity curves, per-example robustness/CE gradient cosines, and attack strength fixed in advance. Compare tuned clean/robust scalarization, constrained robust-accuracy methods, PCGrad/MGDA/CAGrad. Defer for this hardware unless a narrow corruption/non-adversarial robustness study is chosen.
5. **INTERPRETATION:** Demographic fairness versus accuracy could be a meaningful hierarchy only with defensible protected attributes, threshold, and dataset use rights. Gradient conflict may be measured between CE and differentiable group loss (e.g. equalized-odds surrogate) and disaggregated by subgroup, but discrete fairness metrics do not directly supply a stable differentiable secondary. Dataset/legal/social validity and group sample size would dominate this course scope; do not select without explicit justification.

## Baselines, metrics, and scope

- **RECOMMENDATION:** Minimum generic comparison set: (a) primary-only SGD, (b) weighted sum with a predeclared small log-grid and equal tuning budget, (c) PCGrad, (d) one symmetric Pareto method (MGDA or CAGrad), (e) PCD with fixed τ and an explicitly disclosed τ sweep. Add conventional constrained/Lagrangian baseline if a constraint threshold has domain meaning. Match optimizer, schedules, initialization, data order, augmentation, batch size, training steps, and tuning compute.
- **RECOMMENDATION:** For KD include CE-only; ungated weighted KD; gated weighted KD; PCD with ungated KL; gated PCD; confidence-only gate; correctness-plus-confidence gate. This isolates selection from gradient composition. If robustness-to-wrong-teacher is used, make corruptions fixed, seeded, label-preserving protocol splits and disclose 10%/30% corruption rates; do not use test labels to gate training targets.
- **RECOMMENDATION:** For FL include FedAvg as primary baseline and FedProx/SCAFFOLD as heterogeneity controls, plus fairness-aware q-FFL or Ditto and gradient-conflict method FedMGDA+/FedFV if implementation is feasible. Ensure same client partitions, initialization, participation sequence, minibatch order and per-method tuning budgets; report communication rounds and bytes, not only local epoch count.
- **RECOMMENDATION:** For compression include matched target sparsity/rank; tuned group-lasso scalarization; prune-then-finetune or a direct constraint method; report top-1 accuracy, parameter/file size, FLOPs, actual latency under fixed device/runtime, and seed variation. Model size or unstructured zero count alone is not sufficient evidence of deployment efficiency.

## M4 compute estimate and viable project size

These calculations are **INTERPRETATION / estimates**, not benchmarks. Explicit planning assumptions: 50,000 CIFAR training examples; batch 128 gives about 391 optimizer steps per epoch; 40 epochs gives ~15,640 updates/run; a small student CNN/ResNet-8; one CE backward pass + one KD backward pass costs roughly 1.5–2.2× CE-only (frozen teacher forward adds extra inference, PCD needs per-objective gradients); PCD solver overhead is small compared with those passes. Actual MPS throughput, memory use and nondeterministic kernels must be measured in an initial short smoke run before committing to duration. **RECOMMENDATION:** For the assigned coordinator decision, the strongest direct “does PCD benefit?” experiment is a small CIFAR-100 KD study only if the proposal can tightly isolate gate effects and establish observable teacher/student gradient conflict. The strongest already-published fit is federated tail-client progress (FedPCD), but source-paper evidence is recent and not independently reproduced, full repository availability is unresolved, and matching its compute budget is unlikely. Compression has the lowest conceptual ambiguity and official reproducibility assets, but the source paper’s own gradient-cosine evidence says its main empirical advantage was scale imbalance rather than strong conflict. A short gradient-audit pilot should select the research objective before scaling experiments.

## Statistical validity and decision criteria

- **RECOMMENDATION:** Use at least five paired seeds for confirmatory final comparisons if compute allows; share initial weights, data order/partitions, participation sequence and preprocessing between methods. For each seed calculate method differences on the same test set/clients. Report mean, standard deviation, paired differences, and 95% bootstrap confidence intervals over seeds (and, for client-tail metrics, a hierarchical bootstrap over seeds then clients). Five seeds yield low power for small effects; show individual-seed points and treat confidence intervals as descriptive if number of seeds is small.
- **RECOMMENDATION:** Pre-register one primary metric and one main contrast (e.g., gated PCD minus gated weighted KD on student test accuracy, or accuracy at a fixed sparsity). Apply Holm correction to a small family of confirmatory pairwise comparisons; label broad method/τ sweeps exploratory. Do not use repeated test-set checks for τ selection: tune using validation only and evaluate test once at the end. For fairness use per-client held-out test partitions consistent across methods and disclose client count in worst-decile calculation.
- **RECOMMENDATION:** Equalize tuning budget by number of validation evaluations or tuning GPU/CPU hours. Weighted-sum weights must get a defined grid/range, PCD τ values equal or lower search effort, and baselines must not get stale defaults. Publish full grids, selection rule and all seeds; compare both fixed shared hyperparameters and validation-selected settings.
- **RECOMMENDATION:** Avoid leakage from teacher correctness gating on validation/test labels; gate only on the training labels that are legitimately available. If calibration is used, fit temperature on training/validation only and distinguish calibration temperature from distillation temperature. For FL, freeze client splits before hyperparameter selection; report whether client validation/test partitions participate in model selection.
- **HYPOTHESIS — falsification:** “PCD helps” is falsified for a chosen objective if PCD fails to improve its preregistered primary outcome over an equally tuned baseline at matched secondary target, if its paired 95% interval includes a practically negligible/negative effect, or if any gain disappears after matching compute/search budget. Mechanistic claims are falsified if gradient cosines show no material conflict and PCD has no measurable primary/secondary effect beyond scalarized tuning; secondary-progress constraint satisfaction alone is not success if primary quality collapses. Report failed/infeasible QP rates and negative primary alignment, not only selected successful runs.
- **RECOMMENDATION:** Separate theoretical guarantee (QP directional constraint), existing paper evidence (authors’ reported experiments), and this project’s results; do not turn the first two into a claim of expected improvement on the local workload.
